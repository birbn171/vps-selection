## 决定快慢的是线路，不是核数

同一台"2核4G"，放在不同线路上，国内访问体验能差出一倍。机房位置决定延迟下限，线路决定你在晚高峰能不能跑满。

按主用户的所在地选机房，大致是这个顺序：

| 机房 | 国内访问延迟的常见区间 | 主要适合 |
| --- | --- | --- |
| 中国香港 | 30–50ms | 国内用户为主、免备案、要低延迟 |
| 日本、韩国 | 50–80ms | 面向日韩用户，也想兼顾国内访问 |
| 美国西海岸 | 150–200ms | 面向欧美用户，或需要大带宽、大流量 |
| 欧洲 | 250–350ms | 目标用户在当地，国内只做管理后台 |

延迟只是下限，回程线路才是分水岭。CN2 GIA、AS9929、CMI、软银这几类走的是优化线路，普通 163 骨干网晚高峰容易拥堵。雨云在海外节点上用得比较实在：韩国首尔一区走 CN2+CMI+CUG 三网直连，德国法兰克福回程走 CU9929、联通方向优化，日本东京是软银大带宽三网直连，美国洛杉矶分了两个区，其中二区打的是移动 CMI 加联通 AS9929 的双线优化。

需要提醒一句：优化线路值钱，但别把"延迟低"直接等同于"网站秒开"。动态页面的速度还取决于 CPU、磁盘 IO 和你的程序本身。第三方测评里，德国法兰克福的 2 核 4G 机型（AMD EPYC 7452）跑出的 Geekbench 6 成绩是单核约 1125、多核约 2001，这个分数对应个人博客、中小型站点的日常负载是够的，拿来编译大型项目就是另一回事了。

## 买之前先算三笔账：流量、IP、退款

**第一笔，流量怎么算。** 雨云的云服务器分两种口径：一种是不限流量型，带宽给到 20M 到 150M 不等；另一种是大带宽流量叠加型，带宽更大（日本东京最高 100M、德国法兰克福最高 200M），但每月有流量包。后者当月用不完的流量会结转到下个月，不清零，用完不是停机而是限速——日本、德国一般限到 5M，韩国限到 1M，之后可以单独买流量包恢复速度。这个设计比"超量直接扣钱"或"超量关站"要好用，但如果你做的是视频、下载类业务，流量包成本要提前算进预算。

**第二笔，IP 是单独计价的。** 基础价格里通常含 1 个 IPv4，但类型可选。以韩国首尔系列为例，普通 IP 5 元/个/月，本地原生 IP 10 元/个/月，住宅 IP 25 元/个/月。日本东京的基础套餐含 1 个普通 IP，额外 IP 同样 5 元/月。做跨境业务需要"干净"的本地 IP 时，这 25 元/月是真实成本，别只看套餐价。

**第三笔，试用和退款。** 官方提供 7 天内无理由退款，每个账号限 3 次；云服务器和游戏云产品可以 1 元试用一天，每款限 1 次。这条对第一次买境外机器的用户比较关键——先花 1 块钱测一下你所在运营商的晚高峰表现，比看十篇测评都直接。

另外弹性云盘是按 GB 按月计费的，韩国系列 SSD 云盘 0.3 元/GB/月，可以随时扩到 200G，不用一步到位买大盘。
